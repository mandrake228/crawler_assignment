# Асинхронный веб-краулер

Учебный проект: краулер на `asyncio` и `aiohttp`. Сейчас готовы дни 1 и 2 из 7 —
асинхронный HTTP-клиент и разбор HTML.

## Что внутри

| Файл | Что в нём |
| --- | --- |
| `crawler/client.py` | Класс `AsyncCrawler`: загрузка страниц и метод «загрузить и разобрать» |
| `crawler/parser.py` | Класс `HTMLParser`: разбор HTML в данные; сводка страницы `page_summary` |
| `crawler/urls.py` | Проверка адреса и превращение ссылки со страницы в полный адрес |
| `crawler/errors.py` | Ошибки краулера и три категории сбоя |
| `crawler/__init__.py` | Витрина: `from crawler import AsyncCrawler, HTMLParser` |
| `local_site.py` | Учебный сайт на этом компьютере: по нему идут проверки |
| `sample_pages.py` | Учебные страницы HTML: исправная, битая, оборванная, с тегом `<base>`, большая |
| `checks.py` | Помощники проверок: `[ок]`, `[отказ]`, `[РАСХОЖДЕНИЕ]` |
| `demo_day1.py` | Демонстрация дня 1: загрузка страниц |
| `demo_day2.py` | Демонстрация дня 2: разбор HTML |
| `live_day1.py`, `live_day2.py` | Тот же краулер на настоящих сайтах |
| `requirements.txt` | Сторонние пакеты и их точные версии |

## Как запустить

Нужен Python 3.11 или новее. Команды для PowerShell из папки проекта:

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python demo_day1.py
.venv\Scripts\python demo_day2.py
.venv\Scripts\python live_day1.py
.venv\Scripts\python live_day2.py
```

Пакет `aiohttp` — HTTP-клиент краулера. Пакеты `beautifulsoup4` и `lxml` разбирают
HTML; они нужны только модулю `crawler/parser.py` и загружаются при первом разборе.
Без них загрузка страниц и `demo_day1.py` работают, а разбор отвечает ошибкой
`CrawlerError` с командой установки. Пакет `aiofiles` поставлен по заданию
и понадобится в следующих днях, для записи файлов.

Обе демонстрации сами сверяют результат и возвращают код 0, если всё сошлось,
и 1, если есть расхождения. Интернет им не нужен: они запускают учебный сайт
на `127.0.0.1:8421`. Если порт занят, передайте другой:
`.venv\Scripts\python demo_day2.py 8500`. Строки с измеренным временем и числом
шагов цикла событий немного отличаются от запуска к запуску.

`live_day1.py` и `live_day2.py` ходят в интернет. Их вывод зависит от сети
и чужих сайтов.

## Как пользоваться

```python
import asyncio

from crawler import AsyncCrawler, page_summary


async def main():
    crawler = AsyncCrawler(max_concurrent=5)
    try:
        page = await crawler.fetch_and_parse("https://example.com")
    finally:
        await crawler.close()
    print(page["title"], len(page["links"]))
    print(page_summary(page))


asyncio.run(main())
```

### Краулер `AsyncCrawler`

| Метод | Что делает |
| --- | --- |
| `AsyncCrawler(max_concurrent=10)` | Создаёт краулер. По имени задаются таймауты в секундах (`connect_timeout=5`, `read_timeout=15`, `total_timeout=60`) и парсер (`parser=HTMLParser(internal_only=True)`) |
| `await fetch_url(url)` | Возвращает текст страницы. Сбой — ошибка `FetchError` |
| `await fetch_urls(urls)` | Загружает список или кортеж адресов параллельно. Возвращает словарь «URL → текст» только для удачных страниц |
| `await fetch_and_parse(url)` | Загружает страницу и разбирает её. Возвращает результат разбора. Сбой загрузки — та же ошибка `FetchError` |
| `await close()` | Дожидается страниц, которые ещё загружаются, и закрывает сессию. Повторный вызов безвреден. Следующий запрос откроет новую сессию |
| `max_concurrent`, `parser` | Свойства только для чтения: предел конкурентности и парсер |

Закрывать краулер нужно в том же `asyncio.run()`, где шла загрузка.

### Парсер `HTMLParser`

| Метод | Что делает |
| --- | --- |
| `HTMLParser(internal_only=False)` | Создаёт парсер. С `internal_only=True` в результате `parse_html` остаются только ссылки на хост самой страницы |
| `await parse_html(html, url)` | Разбирает текст HTML страницы с адресом `url`. Возвращает результат разбора |
| `make_soup(html)` | Возвращает дерево тегов `BeautifulSoup` для методов ниже |
| `extract_links(soup, base_url)` | Список полных адресов из тегов `<a href>` |
| `extract_text(soup, selector=None)` | Текст страницы; с селектором CSS — текст найденных тегов |
| `extract_metadata(soup)` | Словарь: `title`, `description`, `keywords` |
| `extract_images(soup, base_url)` | Список картинок: `src` и `alt` |
| `extract_headings(soup)` | Список заголовков `h1`–`h3`: `level` и `text` |
| `extract_tables(soup)` | Список таблиц: `headers` и `rows` |
| `extract_lists(soup)` | Список списков `ul` и `ol`: `ordered` и `items` |
| `extract_base_url(soup, url)` | Адрес, от которого считаются относительные ссылки: из тега `<base href>` или `url` |
| `internal_only` | Свойство только для чтения |

На место `soup` годится и документ целиком, и один тег из него: тогда поиск идёт
внутри этого тега. Методы извлечения не меняют дерево. `page_summary(page)`
превращает результат разбора в сводку: счётчики вместо длинных полей и список
`failed`.

## Результат разбора

`parse_html` и `fetch_and_parse` возвращают словарь с постоянным набором ключей.
В нём только строки, числа, списки и словари: он сохраняется в JSON как есть.

| Ключ | Что в нём |
| --- | --- |
| `url` | Адрес страницы. У `fetch_and_parse` — адрес, который просили, даже после перенаправления |
| `title` | Заголовок страницы, тот же, что в `metadata` |
| `text` | Текст без разметки: каждый блок с новой строки, пробелы сжаты. Перевод строки в исходнике страницы новой строки не даёт |
| `links` | Полные адреса `http` и `https`: без якоря, без повторов, в порядке появления |
| `metadata` | `{"title": ..., "description": ..., "keywords": [...]}` |
| `images` | `[{"src": ..., "alt": ...}]` |
| `headings` | `[{"level": 1, "text": ...}]` |
| `tables` | `[{"headers": [...], "rows": [[...], ...]}]` |
| `lists` | `[{"ordered": False, "items": [...]}]` |
| `failed` | Что не удалось извлечь. У исправной страницы список пуст |

В `failed` попадает имя раздела (`text`, `links`, `metadata`, `images`, `headings`,
`tables`, `lists`), слово `base` — не удалось найти базу, ссылки посчитаны от адреса
страницы, или слово `document` — документ не разобран целиком.

## Правила

| Правило | Как оно работает |
| --- | --- |
| Предел конкурентности | Одновременно идёт не больше `max_concurrent` запросов, в том числе у `fetch_and_parse` |
| Одна сессия | Все запросы краулера идут через одну сессию `aiohttp` с пулом соединений |
| Сбой одной страницы не мешает остальным | `fetch_urls` пропускает неудачные адреса, причина пишется в журнал |
| Ответ с кодом от 400 — сбой | Страница с ошибкой не попадает в результат как обычный текст |
| Повторы в списке | Каждый адрес загружается один раз |
| Порядок | Ключи словаря идут в порядке списка |
| Нечитаемые байты | Заменяются знаком `�`, страница остаётся текстом. Если сервер назвал кодировку не для текста или кодировку `punycode`, которая нужна для имён хостов, страница читается как UTF-8 |
| Относительные ссылки | Превращаются в полные по правилам браузера: от адреса, с которого страница пришла, или от тега `<base href>`. Пробелы и управляющие знаки по краям убираются, перевод строки внутри выбрасывается, обратная косая черта в пути читается как обычная |
| Что не ссылка | Пустая ссылка, якорь `#…` и адреса не `http`/`https` (`mailto:`, `javascript:`, `data:`) пропускаются молча |
| Проверка ссылок | Каждый адрес в `links` и `images` проходит ту же проверку, что адрес у `fetch_url`. Негодный отбрасывается с предупреждением в журнале. Ссылки от наследника парсера `parse_html` проверяет заново |
| Таблицы | Первая строка из одних `<th>` — заголовки, остальные — данные. Строки идут по порядку: из `thead`, `tbody`, `tfoot` и прямо из таблицы |
| Заголовок в заголовке | Идёт своей записью; в текст внешнего заголовка не входит |
| Текст | Не входят `<head>`, `<title>`, `<script>`, `<style>`, `<template>`, `<noscript>`, комментарии и подписи `<rt>` — ни без селектора, ни с ним. Текст после закрытых `</body>` и `</html>` входит |
| Вложенные таблицы и списки | Каждый идёт отдельной записью; в текст ячейки или пункта-родителя не входит |
| Битый HTML | Разметку чинит разборщик, ошибки нет |
| Частичный результат | Сбой одного раздела не мешает остальным; его имя попадает в `failed` |
| Не HTML | Ответ с типом не `text/html` и не `application/xhtml+xml` не разбирается: пустой результат, в `failed` — `document` |
| Только внутренние ссылки | С `internal_only=True` остаются ссылки на то же имя хоста, что у адреса страницы; порт и схема не сравниваются, поддомен — другой хост. Имя русскими буквами и его запись для сети (`xn--…`) — один хост. После перенаправления своим считается хост, с которого страница пришла; тег `<base>` на это не влияет |
| Поток разбора | Разбор идёт в одном отдельном потоке и не останавливает цикл событий. Одновременные разборы встают в очередь. Метод извлечения не должен ждать другого разбора: прямой вызов `parse_html` из него — ошибка `CrawlerError` |

## Ошибки

Все ошибки краулера — потомки `CrawlerError`.

| Ошибка | Когда |
| --- | --- |
| `FetchError` | Страницу не удалось загрузить |
| `InvalidArgumentError` | Методу передан негодный аргумент |
| `CrawlerError` | Открытый краулер вызван в другом `asyncio.run()`; порт учебного сайта занят; не поставлены пакеты разбора; `parse_html` вызван из метода извлечения или когда программа уже завершается |

`FetchError` хранит адрес (`url`), категорию (`kind`) и код ответа (`status`).
Исходная ошибка библиотеки лежит в поле `__cause__`.

| Категория | Когда | Исходная ошибка |
| --- | --- | --- |
| `http` | Сервер ответил кодом от 400 или прислал то, что не разобрать как HTTP | `aiohttp.ClientResponseError` |
| `timeout` | Ответ не пришёл вовремя | `asyncio.TimeoutError` |
| `network` | Соединение не установлено или оборвано | `aiohttp.ClientError` |

У бесконечной цепочки перенаправлений кода нет: `status` равен `None`. Ответ,
который не разобрать как HTTP, `aiohttp` помечает кодом 400.

## Негодные аргументы

На негодный аргумент краулер и парсер отвечают ошибкой `InvalidArgumentError`:
краулер — до первого запроса в сеть, парсер — до разбора.

| Аргумент | Что принимается |
| --- | --- |
| `max_concurrent` | Целое число от 1; `True` числом не считается |
| Таймауты | Число секунд больше 0 и не больше 3600 |
| `url`, `base_url` | Строка вида `http://хост` или `https://хост` не длиннее 2000 знаков: порт, если есть, — число до 65535; без логина и пароля; без пробелов и переводов строки |
| `urls` | Список или кортеж таких строк |
| `parser` | `None` или объект `HTMLParser`, в том числе его наследник |
| `html` | Строка, в том числе пустая. Строка, которую разборщик не принял, в `make_soup` — отказ, а в `parse_html` — пустой результат с отметкой `document` |
| `soup` | Дерево тегов от `make_soup` или тег из него |
| `selector` | `None` или строка с селектором CSS |
| `internal_only` | `True` или `False` |
| Аргумент `page_summary` | Результат разбора: словарь со всеми его ключами |

В тексте отказа видно, что получено. Значение со знаком `@` не повторяется:
в нём может быть пароль.

## Журнал

Краулер пишет в журнал `crawler.client` модуля `logging`, парсер — в журнал
`crawler.parser`. Куда выводить журнал, решает программа: `live_day1.py`
и `live_day2.py` включают вывод в терминал.

| Запись | Уровень |
| --- | --- |
| Начало загрузки, успех | `INFO` |
| Сбой загрузки | `WARNING` |
| Итог разбора: адрес, число ссылок и картинок, длина текста | `INFO` |
| Ответ не в формате HTML | `WARNING` |
| Ссылка или адрес картинки отброшены; негодный тег `<base>` | `WARNING` |
| Нет заголовка `<title>`; в документе нет тегов; документ похож на XML | `WARNING` |
| Раздел не извлечён; документ не разобран | `WARNING` |
| Адрес ответа не прошёл проверку: ссылки считаются от запрошенного адреса | `WARNING` |

Об отброшенных адресах в журнал идут первые двадцать записей и одна с числом
остальных; ссылки и картинки считаются отдельно. Значение со страницы показано
коротко и без пароля. Адрес страницы в записях парсера — это адрес, с которого
она пришла: после перенаправления он отличается от запрошенного.

## Чего парсер не делает

- Не выполняет JavaScript: разбирается только разметка, которая пришла в ответе.
- Не ограничивает размер документа и время разбора. Страница с нарочно тяжёлой
  разметкой (сотни тысяч атрибутов у одного тега) занимает поток разбора надолго.
- Не раскрывает `colspan` и `rowspan`, не читает `srcset`, не сохраняет переносы
  внутри `<pre>`.
- Не проверяет то, что вернул наследник, глубже формы значения и адресов
  в `links` и `images`.
- Не берёт в таблицу строку, которую разметка обернула в посторонний тег между
  `<table>` и `<tr>`, например в `<form>`: текст такой строки остаётся в `text`.
- Не во всём повторяет браузер при чтении ссылок. Ссылку вида `///хост/путь` браузер
  ведёт на другой хост, а парсер считает путём на своём. Непроверенный адрес
  в результат при этом не попадает.
- Не спасает от ожидания самого себя: метод извлечения наследника, который ждёт
  другого разбора через `asyncio.run_coroutine_threadsafe`, остановит поток разбора.

## Учебный сайт

`local_site.py` — маленький сайт на `aiohttp`. Его запускают демонстрации и проверки.
Посмотреть на него в браузере: `.venv\Scripts\python local_site.py`, остановить —
Ctrl+C. Порт можно передать аргументом.

| Адрес | Что отвечает |
| --- | --- |
| `/page/имя` | Текст «Страница имя», тип `text/plain` |
| `/slow/мс` | Ответ через столько миллисекунд, до 9999 |
| `/status/код` | Ответ с кодом от 200 до 599 |
| `/drip/точек` | По одной точке каждые 0,1 секунды |
| `/drop` | Обрыв соединения без ответа |
| `/charset/имя` | Байты, которые не читаются как UTF-8; в заголовке названа кодировка `имя` |
| `/html/имя` | Учебная страница HTML: `catalog`, `broken`, `stub`, `based`, `big`. Другое имя — код 404 |
| `/deep/a/b/имя` | Та же учебная страница по более глубокому пути |
| `/moved/имя` | Перенаправление на `/deep/a/b/имя` |
